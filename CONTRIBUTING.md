# Contributing

Hyphaweave is at milestone H0 and the repository is public, but the format is
still a draft. The Inceptless Contributor License Agreement (CLA) is in force as
version 1.0 (2026-11-10, decision #27); every external contribution must pass
the CLA check before it can be merged. The rules below describe how this
repository is built and reviewed.

## Before you contribute: the CLA

Every contributor must accept the [Inceptless Contributor License Agreement,
version 1.0](CLA.md) **before a pull request can be merged**. The CLA allows
Inceptless to offer the projects under other terms while keeping every accepted
contribution available under its open-source license.

- The CLA v1.0 is **in force since 2026-11-10** (decision #27). The signing
  channel is [CLA Assistant](https://cla-assistant.io) (decision #28).
- Signing link: **https://cla-assistant.io/haeliotang/hyphaweave**. The
  repository is public now; the CLA signing check is provided by CLA Assistant.
  Until that check is active for this repository, maintainers will not merge
  external changes, and a pull request cannot be merged.
- This repository does **not** use a Developer Certificate of Origin (DCO).
  A `Signed-off-by` trailer is neither required nor sufficient.

## Development setup

The reference verifier targets Python 3.11 or newer (CI uses 3.12).

```bash
python -m venv .venv
source .venv/bin/activate            # Windows: .venv\Scripts\activate
python -m pip install -c verifiers/python/constraints.txt -e "verifiers/python[dev]"
python -m pip install reuse==5.0.2
```

Dependency versions are pinned in `verifiers/python/constraints.txt`; only the
versions pinned there and in `pyproject.toml` are guaranteed. The local build
environment was Python 3.14; Python 3.11 and 3.12 have not been exercised
locally.

Then run the repository gates from the repository root:

```bash
python tools/make_keys.py --check
python tools/gen_vectors.py --check
python tools/gen_vectors_extra.py --check
python tools/gen_index.py --check
python -m pytest verifiers/python/tests -q
hyphaweave-verify vectors vectors
( cd vectors/frozen/v0.1-candidate && sha256sum -c --strict SHA256SUMS )
python tools/check_frozen.py
hyphaweave-verify vectors vectors/frozen/v0.1-candidate
python tools/check_schemas.py
python tools/check_external.py
python tools/anti_verification.py
python tools/byte_flip_gate.py
python tools/check_spec_examples.py
reuse lint
```

These are the same commands as [`.github/workflows/ci.yml`](.github/workflows/ci.yml).
A pull request must leave all of them passing. The workflow runs on GitHub once
changes are pushed; this document does not claim that a particular CI run
passed, so run the commands locally as well.

## Repository conventions

- **Language.** All repository text is English, except `README.zh-CN.md`, which
  is the Chinese translation of the root README. Contact addresses in the
  repository are `support@inceptless.com` only.
- **SPDX information.** Every file carries SPDX metadata under the REUSE
  convention. Markdown, Python and YAML files start with an inline header;
  JSON, binary test material and a few other files are covered by
  `REUSE.toml`. Do not add comments to `.json` files.
- **Canonical JSON.** Any JSON file that the format digests or signs must
  contain exactly the canonical bytes defined by the specification (WR-CJ),
  optionally followed by exactly one trailing LF. Do not hand-format those
  files with a pretty-printer; tools may regenerate them only through the
  canonical writer.
- **Test keys only.** `vectors/keys/` contains synthetic keys that are
  **deliberately public test material**. Never add a real private key, a real
  seed, personal data or anything from a keychain. Never use the test keys for
  anything other than running this repository's tests.
- **Offline and deterministic.** The verifier must not use the network, the
  wall clock, the locale, the time zone, the current directory or environment
  variables in its output. Two runs on any machine must produce byte-identical
  JSON reports for the same input.
- **Expectations are authored, not observed.** `expected.json` files and their
  verdicts/error codes are written from the specification, never generated by
  running the verifier. Vector generators must not import the verifier.
- **Tests must fail for the right reason.** A negative vector names the exact
  expected error code; a rejection with a different code is a failing test.
- **Gates are real, not sampled.** The ablation gate mutates verifier source and
  requires every mutation to be caught by at least one vector; the byte-flip gate
  flips every byte of every positive vector; do not weaken either to make a
  change pass.
- **Specification examples are tested.** Complete JSON examples in `spec/` are
  validated by `tools/check_spec_examples.py`; a change to an example must leave
  that gate green.
- **Old versions are never abandoned.** `vectors/frozen/v0.1-candidate/` is the
  candidate regression set: once v0.1 is accepted by J1/J2 it is frozen and its inputs
  and expected conclusions must never change. New vectors go elsewhere.
- **Do not name third-party products or AI services in repository text.** Keep
  user-visible text focused on the format and the project.

## Changes to the format

`weave-record/1` follows a written-proposal process: changes are recorded in a
decision log and, at this stage, approved by the founder before they reach the
specification. Breaking changes bump the format version; registered kinds
evolve additively. New kind schemas are proposed together with a specification
page, a JSON Schema and conformance vectors. If a rule looks ambiguous, do not
silently resolve it: mark it `PROVISIONAL` in the specification and raise it as
an open question rather than inventing an answer.

## Pull request checklist

- [ ] The CLA check passes (the CLA is signed; the repository is public).
- [ ] The change is within one area (specification, schemas, vectors, verifier,
      tooling, repository metadata) where practical.
- [ ] New behaviour has tests, and negative test cases name their expected
      error code.
- [ ] `reuse lint` passes; new files carry SPDX information.
- [ ] All gates above pass locally; paste the commands and results in the pull
      request.
